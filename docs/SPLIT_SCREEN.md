# 平板分屏（Split Screen）设计规范

> 配套视觉稿：`docs/designs/split-screen-redesign.html`
> 状态：设计已评审，待实现
> 范围：仅 mobile shell（内置面板）。外接显示器走桌面布局，不受本规范影响。
> 版本：v2（2026-11-11，纳入入口扩展、组合卡片、分割条增强等决策）

---

## 1. 目标

在 Denial 的 mobile shell 中提供双应用分屏，交互对齐 Android 平板：

- 两条入口：recents 拖拽、launcher 长按图标拖拽
- 分屏对绑定为一张 recents 卡片，可在多对分屏间切换
- 分屏方向由输出宽高比自动决定：**横屏左右、竖屏上下**
- 最大化复用已有基础设施，不引入第二套窗口管理体系

## 2. 术语

| 术语 | 含义 |
|---|---|
| recents | 上划进入的任务预览视图（现有功能） |
| 放置区（drop zone） | 拖拽激活的半屏虚线区域，松手即固定 |
| 触发区（trigger zone） | 竖屏顶部/底部 25% 区域，拖入即分屏 |
| 分界线（threshold） | 竖屏约 55% 屏高的红色虚线，区分"关闭"与"上分屏" |
| 选择器（picker） | 固定一侧后，铺在另一侧的半透明任务选择浮层 |
| 单应用分屏态 | 只固定了一侧、另一侧留空的状态，可随时补齐 |
| 分割条（divider） | 分屏中间的可拖动手柄，调节两侧比例 |
| 分屏对（pair） | 已形成双应用分屏的组合，在 recents 中显示为一张卡片 |
| 激活侧（active side） | 当前获得焦点的一侧，接收输入与返回键 |

## 3. 入口

### 3.1 recents 入口（主）

上划进入 recents → 拖任务卡片到屏幕一侧 → 在选择器中补齐第二个应用。

### 3.2 launcher 入口（辅）

桌面上**长按应用图标拖向屏幕一侧**：

- 当前前台应用自动占据另一侧（若前台无应用，则拖入侧即为单应用分屏态）
- 松手即形成分屏，无需经过 recents
- 拖拽中同样显示放置区与比例预览

两条入口的拖拽判定、放置区视觉、后续流程完全一致。

## 4. 状态机

```
全屏态
  │  上划（recents）/ 长按图标拖向边缘（launcher）
  ▼
拖拽中（放置区 + 比例预览）
  │  松手（到达放置区/触发区）
  ▼
单应用分屏态（一侧固定，另一侧选择器/留空）
  │  在选择器中点选任务
  ▼
双应用分屏态（分屏对）
  │  在 recents 中上划关闭一侧
  ▼
全屏态（另一侧扩展）
```

合法跳转：

- 拖拽未过阈值松手 → 卡片/图标弹回，不进入分屏
- 选择器关闭（点空白/向下划）→ 单应用分屏态
- 单应用分屏态 → 从 recents 再拖入一个应用 → 双应用分屏态
- 双应用分屏态 → 分割条拖到极限 → 全屏态
- 双应用分屏态 → recents 中切换到另一对分屏卡片 → 当前对退后台，新对上台
- 双应用分屏态 → 从 recents **主动**拖入第三个应用 → **拒绝**（提示先退出当前分屏）
- 双应用分屏态 → 通知/外部 intent 打开新应用 → **替换非激活侧**

## 5. 手势与导航规范

### 5.1 手势消歧

关闭与分屏共用"在 recents 拖卡片"这一个起点，按**主位移方向 + 到达区域**判定，跟手实时预览，松手提交。

**横屏**

| 手势 | 判定 | 行为 |
|---|---|---|
| 上划 | 上划位移超过卡片高度 40% | 关闭应用（保留轻划手感） |
| 拖向左右边缘 | 卡片中心越过屏幕宽度 28% | 激活该侧放置区，松手固定 |

**竖屏**

| 手势 | 判定 | 行为 |
|---|---|---|
| 向上拖 | 拖过约 55% 屏高（分界线） | 顶部触发区点亮，松手 = 上分屏 |
| 向上拖 | 未过线松手 | 关闭应用 |
| 向下拖 | 拖入底部 25% 触发区 | 松手 = 下分屏 |
| 向下轻划 | 未到底部触发区 | 无操作，卡片弹回 |

分界线在拖拽中**始终可见**（红色虚线 + 标签）。

### 5.2 阈值总表

| 参数 | 数值 |
|---|---|
| 横屏分屏激活（卡片中心） | 屏幕宽度 28% |
| 竖屏触发区 | 屏幕高度 25%（顶/底） |
| 竖屏关闭/分屏分界线 | 屏幕高度 55% |
| 关闭位移阈值 | 卡片高度 40% |
| 分割条 50% 磁吸区 | ±3% |

### 5.3 系统按键与手势（分屏态）

| 输入 | 行为 |
|---|---|
| 返回键 | 关闭/返回**激活侧**（非激活侧不动） |
| 上划 | 进入 recents（分屏对显示为一张卡片，见 7.2） |
| Home 键 | 无（Denial mobile 不设 Home 键） |
| 点按一侧 | 该侧成为激活侧（焦点高亮切换） |

## 6. 布局规则

1. **方向**：由输出宽高比自动决定，横屏左右、竖屏上下，无用户开关。
2. **默认比例**：53 : 47（首拖入侧略大），与选择器默认宽度一致。
3. **比例限制**：20% – 80%。分割条拖到 ≤10% 或 ≥90% 进入退出预览，**松手才退出**。
4. **复位**：双击分割条恢复 53 : 47。
5. **磁吸**：拖过 ±3% 区间（47%–53%）时吸附到 50 : 50。
6. **旋转**：
   - 分屏进行中旋转，方向随宽高比翻转（左右 ↔ 上下）；
   - 比例记忆不变，按短边占比保持；
   - 旋转动画期间冻结 configure 更新，落地后一次性下发，避免抖动。
7. **状态栏占位**：各分屏区域顶部保留 48 逻辑像素状态栏高度，按区域获得 inset。

## 7. 比例适配判定（A）

**不读 `resizeableActivity` 作为拒绝依据。** Android 的 manifest 标志是 Activity 栈概念，而 Wayland 客户端层面暴露的是 xdg size hints（min/max size、宽高比约束）。判定按以下优先级：

1. 客户端声明了固定尺寸或宽高比（xdg min=max）→ 放置区显示其**声明的比例**，允许放入（用户自己判断）
2. 客户端无约束 → 放置区显示**目标区域比例**的实时预览（见 9.3）
3. 仅当客户端的最小尺寸 > 目标区域尺寸（物理上放不下）→ 放置区置灰并提示"该应用最小需要 XXX"

核心原则：**横屏游戏左右分屏比例不对，上下分屏可能就合适——比例问题交给用户判断，compositor 只拦物理上放不下的情况。**

## 8. 视觉规范

### 8.1 放置区 / 触发区

- 圆角 22px，accent（`#6d5bd0`）2px 虚线边框，填充 `rgba(109, 91, 208, 0.14)`
- 内阴影 `inset 0 0 60px rgba(109,91,208,.12)`
- 中央文案："放到左侧" / "拖到这里 = 上分屏"，17px 半粗
- 内部叠加**比例预览**（见 9.3）

### 8.2 关闭反馈

- 圆角 22px，关闭色（`#c9483f`）2px 虚线边框，填充 `rgba(229, 83, 75, 0.12)`
- 文案："松手关闭"

### 8.3 分界线（仅竖屏）

- 横贯屏幕 2px 红色虚线（`rgba(229, 83, 75, .45)`）
- 右侧浮动标签："分界线 · 约 55% 屏高"，白底胶囊

### 8.4 分割条

- 宽 10px，半透明白底（`rgba(255,255,255,.5)`）
- 中央手柄：46px 圆形，白底、1px 边框、`0 4px 14px rgba(20,22,28,.22)` 阴影
- 光标：横屏 `col-resize`，竖屏 `row-resize`
- 拖过 ±3% 区间时磁吸到 50 : 50（手柄轻微脉冲反馈）

### 8.5 退出预览

- 分割条拖到 ≤10% / ≥90%：该侧缩小 + 中央提示"松手退出分屏"，半透明遮罩
- **松手才退出**；拖回区间内则预览消失，分屏保持

### 8.6 拖拽中的卡片

- 保持原始尺寸，`rotate(-2.5deg) scale(.92)`，阴影加深
- 其余任务卡片降透明度作为背景层，避免误触
- 叠加**目标区域比例实时预览**（见 9.3）

### 8.7 选择器

- 铺在被遮半屏，半透明深色（`rgba(18,18,26,.58)`）+ 22px 背景模糊
- 列表项：缩略图 64px 圆角 10px + 应用名 + 状态行 + 右侧"打开 →"
- **浮层不抢占渲染**：已固定侧保持实时刷新（视频/动画不暂停）

### 8.8 激活侧高亮

- 激活侧：极淡的 glass 描边（1px accent 内发光，`rgba(109,91,208,.25)`）
- 非激活侧：无装饰，仅内容降 4% 亮度
- 点按任一侧即时切换，动画 120ms
- 分屏刚形成时默认**先拖入侧**为激活侧

## 9. 关键交互细则

### 9.1 recents 中的分屏对（B）

- 分屏对显示为**一张卡片**，内容为该对的拼接预览（左/上应用 + 右/下应用）
- 多对分屏可并存，recents 中各占一张卡片，点按切换（当前对退后台）
- 卡片操作：上划 = 关闭整对（两侧都关）；拖出 = 整对进入全屏（先拖侧变全屏）
- 分屏中从 recents **主动拖入第三个应用 = 拒绝**，toast 提示"请先退出当前分屏"

### 9.2 分割条增强（C）

- **双击手柄交换两侧应用**：两侧内容带翻转动画互换，比例保持
- 拖到极限的退出预览见 8.5
- 磁吸见 8.4

### 9.3 拖拽比例实时预览（L）

拖拽过程中，放置区内叠加该应用在目标区域的比例示意：

- 卡片渐变为目标区域宽高比的半透明缩略图（不是静态 ghost）
- 示意下方标注实际像素："约 800×1700"
- 客户端声明了固定尺寸时，示意按声明比例绘制（见第 7 节）
- 松手后缩略图无缝展开为真实窗口

### 9.4 外部 intent 打开新应用（I）

分屏态下收到通知点击 / 外部 intent：

- 新应用**替换非激活侧**，激活侧保持不动
- 被替换方退后台（不关闭，回到 recents）
- 替换时非激活侧先淡出（150ms）再交叉淡入新应用（200ms）

## 10. 与现有系统的接口

### 10.1 window_layout（compositor）

分屏作为新布局算法接入 `compositor/src/bin/deniald/window_layout.rs`：

- 布局实现只算矩形，不感知 Wayland/Smithay/焦点/客户端配置
- 新增 `WindowLayoutKind::Split`，由输出宽高比在运行时确定二分方向
- 前端 adapter 负责把布局矩形翻译成 configure，与现有 Dwindle/Scrolling 同一路径

### 10.2 per-app virtual output scaling

分屏与 commit `176514c` **同源**：每个分屏区域 = 一份虚拟输出尺寸。

- configure 尺寸、size hints、insets 在出口除以 k；xdg geometry、popup 位置、IME 光标矩形在入口乘以 k
- `applicationScales` 按 app id 解析后作用于所在区域

### 10.3 insets 与 IME

- 各应用按所在区域获得 inset（复用 `denial-insets-v1` 与现有 48px 状态栏逻辑）
- 软键盘归属**激活侧**：该侧内容上推，非激活侧不动
- 与 fcitx 共用同一焦点事件源，分屏不引入额外输入状态

### 10.4 Droidloom 的 Android 应用

- Android 窗口作为普通 Wayland 客户端参与分屏，按区域接收 configure
- **不使用 Android 自带分屏**，由 Denial 统一管理，避免两层分屏互相干扰

## 11. 边界情况

| 场景 | 行为 |
|---|---|
| 拖拽未过阈值松手 | 卡片/图标弹回，放置区淡出，无确认弹窗 |
| 选择器关闭未选应用 | 进入单应用分屏态；之后可随时补齐，或拖出退出 |
| 只有一个任务 | 仍可拖向一侧；选择器显示"打开其他应用"入口（launcher） |
| 主动从 recents 拖入第三个应用 | 拒绝，提示"请先退出当前分屏" |
| 通知/外部 intent 打开新应用 | 替换非激活侧，被替换方退后台 |
| 分屏对在 recents 中的操作 | 上划 = 关闭整对；拖出 = 先拖侧变全屏；点按 = 切换当前对 |
| 分屏中从 recents 关闭一侧 | 另一侧平滑扩展为全屏，分割条收起；扩展走 liquid motion 曲线 |
| 竖屏向下轻划 | 无操作，弹回 |
| 分屏中旋转 | 方向翻转、比例按短边占比保持；动画期间冻结 configure |
| 接外接显示器 | 分屏只存在于 mobile 输出；窗口可跨屏拖到 desk，按桌面策略放置 |
| 客户端最小尺寸 > 区域尺寸 | 放置区置灰 + 提示"该应用最小需要 XXX"（唯一硬性拒绝） |

## 12. 明确不做（YAGNI）

- 三应用分屏
- 画中画浮窗
- 自由窗口（freeform）
- **比例按应用对记忆**（每次分屏重置为默认 53 : 47）
- **后台被杀后的分屏占位恢复**（Linux 环境不杀后台，lmkd 不做此场景）
- 分屏内直接拖拽交换位置（用分割条双击交换替代）

## 13. 验收标准

- [ ] 横屏：recents 上划关闭应用（回归现有行为）
- [ ] 横屏：拖卡片到左/右边缘 → 放置区 + 比例预览 → 松手固定
- [ ] 竖屏：上拖过 55% 分界线上分屏；未过线关闭；下拖到底下分屏；下轻划弹回
- [ ] 选择器点选第二个应用形成分屏对；已固定侧持续渲染
- [ ] 分割条：拖动调节（20–80%）、50% 磁吸、双击复位、双击手柄交换两侧
- [ ] 分割条拖到极限：退出预览出现，松手退出，拖回保持
- [ ] recents 中分屏对为单卡片：点按切换、上划关整对、拖出先拖侧全屏
- [ ] 主动拖入第三个应用被拒绝并提示
- [ ] 通知点开新应用替换非激活侧，激活侧不动
- [ ] 激活侧高亮，点按切换
- [ ] 拖拽中放置区显示目标比例实时预览（含实际像素标注）
- [ ] 客户端最小尺寸超限时放置区置灰并提示
- [ ] 分屏中旋转：方向翻转、比例保持、无抖动
- [ ] 返回键关闭/返回激活侧
- [ ] launcher 长按图标拖向边缘直接分屏
- [ ] Droidloom 应用分屏后正确重新布局

## 14. 实现落点（参考）

| 层 | 位置 | 工作 |
|---|---|---|
| compositor 布局 | `compositor/src/bin/deniald/window_layout.rs`（+ `window_layout/`） | 新增 `Split` 布局、方向判定、比例约束与磁吸、旋转保持 |
| compositor 前端 | `wayland_frontend/` 相关 adapter | 布局矩形 → configure；per-app scale、insets、size hints 读取与换算 |

| shell（分屏态） | `plugins/denial_desktop` 状态层 | 分屏对状态机、激活侧、分割条交互、外部 intent 路由 |
