# 平板分屏（Split Screen）设计规范

> 配套视觉稿：`docs/designs/split-screen-redesign.html`
> 状态：设计已确认，按 v3 实现
> 范围：仅 mobile shell（内置面板）。外接显示器走桌面布局，不受本规范影响。
> 版本：v3（2026-11-12，改为「两张卡片」模型：入口、分割条、选择器、配对卡片全部重做）

---

## 1. 目标

在 Denial 的 mobile shell 中提供双应用分屏，交互对齐 Android 平板但更简单：

- **两张卡片并排**，而不是把屏幕切成两半；应用保留自己的圆角，中间 14px 间隙
- 分屏方向由输出宽高比自动决定：**横屏左右、竖屏上下**
- 入口只有一个：**在 recents 长按卡片拿起，松手到左侧或右侧**
- 第二侧直接铺**应用缩略图**，点哪个补哪个
- 最大化复用已有基础设施（窗口矩形仍由合成器决定）

## 2. 术语

| 术语 | 含义 |
|---|---|
| recents | 上划进入的任务预览视图（现有功能） |
| 卡片（card） | 分屏中的一侧应用，圆角 20、带自己的窗口装饰 |
| 间隙（gutter） | 两张卡片之间的 14px 空隙 |
| 把手（handle） | 浮在间隙里的 38px 分割条，含 ✕ 与拖动条 |
| 拿起（pickup） | 在 recents 长按卡片 380ms，卡片缩小并进入可放置状态 |
| 放置区（drop zone） | 拿起后左右（竖屏为上下）各 **40%** 的虚线区域，中间 **20%** 为取消区 |
| 取消区 | 两个放置区之间的 20%，在此松手回到 recents，不进入分屏 |
| 单应用分屏 | 只固定了一侧、另一侧在选应用的状态 |
| 分屏对（pair） | 已形成的双应用组合，在 recents 中是一张卡片 |
| 激活侧 | 当前获得焦点的一侧，接收键盘、返回键与通知 |
| 配对卡片 | recents 中代表整个分屏对的那一张卡 |

## 3. 入口

### 3.1 recents 入口（唯一入口）

上划进入 recents → **长按卡片 380ms 拿起** → 左右两块放置区同时出现 → 拖到任一侧松手。

- 拿起后卡片缩小到约 `360 × 460`、`scale .94 / rotate -2°`，其余卡片淡到 25%
- 两块放置区**同时出现**（不是拖到边缘才出现），手指所在的一侧高亮
- 放置区里标注该侧的实际像素（`50% · 约 800 × 952`），松手前就知道结果
- 在中间 20% 松手 = 取消，卡片回到 recents

### 3.2 手势消歧

长按拿起是一个**独立手势**，与现有 recents 手势不冲突：

| 手势 | 行为 |
|---|---|
| 短按卡片 | 打开应用（现有） |
| 竖直上滑卡片 | 关闭应用（现有） |
| 水平拖动 recents | 翻卡片（现有） |
| **长按 380ms 后拖动** | 拿起卡片，进入放置流程 |
| 拿起后拖回中间松手 | 取消，回到 recents |

> 不设「分界线」「55% 阈值」「上/下三区」等额外规则：竖直方向的手势只属于原有的关闭，分屏全部由拿起后的 40/20/40 判定。

### 3.3 launcher 入口（暂缓）

v3 不提供 launcher 长按拖拽入口：它与桌面图标的长按整理/卸载手势冲突，学习成本高，而 recents 拿起已经覆盖完整流程。后续如需要，只加一个「长按图标 → 菜单里的分屏项」，不做拖拽。

## 4. 状态机

```
全屏态
  │  recents：长按拿起卡片
  ▼
拿起态（40% / 20% / 40% 放置区）
  │  松手到任一侧               │  中间松手
  ▼                             ▼
单应用分屏（另一侧铺缩略图）      回到 recents
  │  点一个应用缩略图
  ▼
双应用分屏（两张卡片 + 把手）
  │  ✕ / 分割条拖到边缘 / 打开第三个应用 / 上滑回桌面
  ▼
全屏态（保留激活侧）
```

合法跳转：

- 拿起后在中间松手 → 取消，无确认弹窗
- 单应用分屏 → 点缩略图补齐 → 双应用分屏
- 单应用分屏 → 点「全部应用」→ launcher 铺进这一侧，选新应用直接落位
- 双应用分屏 → ✕ 或分割条拖过 10% → 退出分屏（激活侧保留全屏）
- 双应用分屏 → 打开第三个应用 / 上滑回桌面 → 分屏结束（当前行为，后续可改为「保留配对卡片」）
- 双应用分屏 → 通知 / 外部 intent 打开新应用 → **替换非激活侧**
- 双应用分屏 → 从 recents 再拖入第三个应用 → **拒绝**，提示「先退出当前分屏」

## 5. 手势与阈值

### 5.1 放置区（拿起态）

| 参数 | 数值 |
|---|---|
| 长按拿起 | 380ms |
| 左右放置区 | 各 40% 屏宽（竖屏：各 40% 屏高） |
| 中间取消区 | 20% |
| 拿起卡片尺寸 | 约 360 × 460（横屏） |
| 进入放置 | 卡片中心进入 40% 区域即算 |

### 5.2 分割条

| 参数 | 数值 |
|---|---|
| 比例范围 | 20% – 80% |
| 默认比例 | 50 : 50 |
| 磁吸 | 47%–53% 吸附到 50 : 50（±3%） |
| 复位 | 双击把手 → 50 : 50 |
| 退出预览 | 拖到 ≤10% 或 ≥90%，该侧红虚线，**松手才退出** |
| 把手尺寸 | 38 × 86，顶部 ✕ 28 圆钮 |

### 5.3 系统按键（分屏态）

| 输入 | 行为 |
|---|---|
| 返回键 | 关闭/返回**激活侧** |
| 上划 | 进入 recents（配对显示为一张卡片） |
| 点按一侧 | 该侧成为激活侧 |
| 软键盘 | 只上推激活侧；隐藏时两侧都恢复 |

## 6. 布局规则

1. **方向**：由输出宽高比自动决定，横屏左右、竖屏上下，无用户开关。
2. **两张卡片**：`gap 14px`，外侧边距 14px，圆角 20px；卡片内保留应用自己的窗口装饰。
3. **默认比例**：50 : 50。
4. **比例限制**：20% – 80%，分割条拖到 ≤10% 或 ≥90% 进入退出预览，松手才退出。
5. **复位**：双击把手恢复 50 : 50。
6. **旋转**：方向随宽高比翻转；比例按短边占比保持；动画期间冻结 configure，落地后一次性下发。
7. **状态栏**：窗口由合成器扣掉 45 逻辑像素状态栏；外壳绘制的层（缩略图选择器）自己加同样的顶部内边距。
8. **键盘内推**：只对激活侧应用键盘 inset，非激活侧不动。

## 7. 比例适配判定

不读 `resizeableActivity`。按 Wayland 客户端实际暴露的约束判定：

1. 客户端声明固定尺寸或宽高比（xdg min=max）→ 放置区按声明比例绘制预览，允许放入
2. 无约束 → 按目标区域比例实时预览
3. 仅当最小尺寸大于目标区域（物理放不下）→ 放置区置灰并提示「该应用最小需要 XXX」

## 8. 视觉规范

### 8.1 卡片

- 圆角 20，白色/应用自身背景，`0 1px 2px rgba(20,22,28,.08)`
- 激活侧：`inset 0 0 0 1.5px rgba(109,91,208,.55)` + 轻微内发光
- 非激活侧：亮度 94%

### 8.2 分割条

- 38 × 86 圆钮，半透明白（`.92`）+ `blur(10)`，`0 6px 20px rgba(20,22,28,.22)`
- 中央两条 3 × 22 的灰色拖拽条
- 顶部 28px 圆形 ✕（直接退出分屏）
- 竖屏时旋转 90°（86 × 38，拖拽条横置）
- 光标：横屏 `col-resize`，竖屏 `row-resize`

### 8.3 放置区

- 40% 区域：`rgba(109,91,208,.22)` 填充 + `rgba(178,167,255,.9)` 2px 虚线 + 22 圆角
- 文案：「放到左侧 / 放到右侧 / 拖到这里 = 上分屏 / 下分屏」，18px 600
- 下方小字：`50% · 约 800 × 952`
- 未激活的一侧：填充 10%、虚线 40% 不透明、文字 55% 不透明
- 中间 20% 取消区：不画边框，仅一个淡文字「松手取消」

### 8.4 退出预览

- 被压缩一侧缩到 180px，盖红色虚线（`rgba(229,83,75,.6)`）+ `rgba(229,83,75,.14)` 填充
- 文案：「松手关闭这一侧」
- 拖回区间内预览消失，分屏保持

### 8.5 缩略图选择器

- 铺在空的一侧，深色 `rgba(18,18,26,.72)` + 22px 背景模糊
- **2 列应用缩略图**（4:3、圆角 16），用与 recents 同一套实时预览，下方应用名
- 最后一张「全部应用」：虚线框 + 九宫格点阵，点开把 launcher 铺进这一侧
- 固定侧保持实时渲染（视频/动画不暂停）

### 8.6 配对卡片（recents）

- 一张卡片：左右（竖屏上下）各一半实时预览，中间细分割线
- 右下角徽标「分屏 50:50」，accent 实底白字
- 点按恢复分屏；上划关闭两侧；长按拖出一侧 → 该侧先变全屏

## 9. 关键交互细则

### 9.1 激活侧

- 默认：先放进去的一侧为激活侧
- 点按任一侧立即切换（120ms）
- 键盘、返回键、通知点击都作用于激活侧

### 9.2 分割条

- 拖动实时改两张卡片的宽度（合成器重算矩形）
- 47%–53% 吸附 50:50，把手轻微脉冲
- 双击把手复位 50:50；拖到 ≤10%/≥90% 进入退出预览

### 9.3 外部 intent

- 分屏中收到通知点击/外部 intent：新应用**替换非激活侧**，激活侧不动
- 被替换方退后台（不关闭），替换时先淡出 150ms 再淡入 200ms

### 9.4 键盘

- 软键盘归属激活侧：只推激活侧的卡片内容
- 键盘弹出/收起不改变分割条位置

## 10. 与现有系统的接口

### 10.1 合成器

- 分屏状态由 `WaylandFrontend.mobile_split`（`wayland_frontend/mobile_split.rs`）持有：两个窗口 id、方向、比例
- `mobile_window_geometry()` 是唯一矩形来源：分屏成员返回各自半边，`second == 0` 表示另一侧留空
- Shell → 合成器：`WindowRequestKind.SplitWindows / UpdateSplitRatio / EndSplit`
- 比例 clamp 20%–80% 在合成器侧再做一次，外壳传什么都不会越界

### 10.2 per-app virtual output scaling

- 每个分屏区域 = 一份虚拟输出尺寸；configure 仍走 `client_size(rect.size)`，按 app id 解析 k
- 一个 client 的所有窗口共享一个 `client_scale`；同一 app 同时出现在两侧暂不支持

### 10.3 insets 与 IME

- 两侧各自获得 inset（复用 `denial-insets-v1`）
- 软键盘只推激活侧；输入焦点切到另一侧时键盘跟随

### 10.4 Droidloom

- Android 窗口作为普通 Wayland 客户端参与分屏，按区域接收 configure
- 不使用 Android 自带分屏

## 11. 边界情况

| 场景 | 行为 |
|---|---|
| 拿起后在中间松手 | 取消，回到 recents，无提示 |
| 选择器未选应用就关闭 | 回到全屏（v3 暂不做「单应用分屏常驻」） |
| 只有一个任务 | 仍可拿起；选择器为空时显示「没有其他打开的应用」，只能取消 |
| 分屏中从 recents 拖入第三个应用 | 拒绝，提示「先退出当前分屏」 |
| 通知/外部 intent | 替换非激活侧 |
| 分屏中从 recents 关闭一侧 | 另一侧平滑扩展为全屏（液体动效） |
| 分屏中旋转 | 方向翻转、比例按短边保持；动画期间冻结 configure |
| 接外接显示器 | 分屏只存在于 mobile 输出；窗口可拖到 desk，按桌面策略放置 |
| 客户端最小尺寸超限 | 放置区置灰 + 提示（唯一硬性拒绝） |
| 打开第三个应用 / 上滑回桌面 | 分屏结束，保留激活侧全屏 |

## 12. 明确不做（YAGNI）

- 三应用分屏
- 画中画浮窗
- 自由窗口（freeform）
- **launcher 长按拖拽入口**（后续只考虑菜单项）
- **比例按应用对记忆**（每次分屏重置为 50 : 50）
- **后台被杀后的分屏占位恢复**
- 分屏内直接拖拽交换位置（用分割条双击交换替代）

## 13. 验收标准

- [ ] recents 长按卡片 380ms：卡片缩小、其余淡出、左右放置区同时出现
- [ ] 左右各 40%、中间 20%：中间松手取消，两侧松手进入单应用分屏
- [ ] 单应用分屏：另一侧铺应用缩略图（2 列），点选补齐；「全部应用」可用
- [ ] 双应用分屏：两张卡片、14px 间隙、把手浮在中间
- [ ] 分割条：拖动 20–80%、47–53% 吸附 50:50、双击复位、拖到 ≤10% 出现关闭预览、松手退出
- [ ] ✕ 直接退出分屏
- [ ] 点按一侧切换激活侧；键盘只推激活侧
- [ ] 返回键作用于激活侧
- [ ] recents 中分屏对为一张配对卡片：点按恢复、上划关两侧、长按拖出一侧变全屏
- [ ] 打开第三个应用 / 上滑回桌面 → 分屏结束
- [ ] 外部 intent 替换非激活侧
- [ ] 旋转：方向翻转、比例保持、无抖动
- [ ] 客户端最小尺寸超限时放置区置灰并提示
- [ ] Droidloom 应用分屏后正确重新布局
